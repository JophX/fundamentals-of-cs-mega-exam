6. Haskell: fold, list → int, compress / decompress, reverse

The idea in plain words

Haskell has no loops and no variables that change. Instead of “repeat this for each element”, you say: “what is the answer for the empty list?” and “if I already had the answer for the rest of the list, how do I get the answer for the whole list?”. That’s it. Every exam function is one of two patterns: plain recursion, or recursion with an accumulator. Learn both patterns and you can write all of them.

6.1 The five pieces of syntax you need

countA :: String -> Int
countA [] = 0
countA (c:cs) = if c == 'a' then 1 + countA cs else countA cs
  • [] is the empty list; (x:xs) matches a non-empty list: x = first element (head), xs = the rest (tail). A String is a list of Char, so "abc" = 'a' : 'b' : 'c' : [].
  • x : xs puts an element in front (O(1)). xs ++ ys glues two lists (costs O(length xs)).
  • Guards — a cleaner if/else:
countA :: String -> Int
countA [] = 0
countA (c:cs)
  | c == 'a'  = 1 + countA cs
  | otherwise = countA cs
  • where — local helper definitions, written after the function body (indented).
  • Lambda — an unnamed function: \x -> x * 2 is “the function that takes x and returns x*2”. \acc x -> acc + x takes two arguments.

6.2 Pattern 1 — plain recursion

Recipe
  1. Write the type signature.
  2. Base case: f [] = ... — the answer for the empty list.
  3. Recursive case: f (x:xs) = ... x ... f xs ... — assume f xs already works (“trust the recursion”) and combine it with x.
  4. Test by hand on a 2–3 element list.




map (*2) [1,2,3]
filter even [1..10]



6.3 Pattern 2 — the accumulator (“carry the answer so far”)


Intuition

Like a loop with a running total: acc = start; for x in list: acc = update(acc, x); return acc. In
Haskell the “loop” is a helper function go that takes the rest of the list and the accumulator. When the
list is empty, the accumulator is the answer.




template :: [Int] -> Int
template xs = go xs 0            -- 0 = the starting value of the accumulator
  where
    go []     acc = acc          -- list finished: the accumulator is the answer
    go (y:ys) acc = go ys (acc + y)   -- update the accumulator, continue with the rest



This is also tail recursion: the recursive call is the very last thing done, so nothing has to be remembered
on the stack (it runs like a loop). That is what “write a tail-recursive function” (2017 exam) asks for.

6.4 Writing foldr and foldl yourself


Intuition

A fold is just “the accumulator pattern, packaged as a library function”. You give it three things: a
combining function, a starting value, and the list. It combines everything into one value.


    
  
  • foldl (left): starts from the left, carrying the accumulator:
    foldl f z [1,2,3] = f (f (f z 1) 2) 3. The accumulator is the first argument of f.
    • 
  
  • foldr (right): builds from the right:
    foldr f z [1,2,3] = f 1 (f 2 (f 3 z)). The element is the first argument of f.
    • 









How to remember the definitions (rewrite them from this)

    
  
  • Both: on the empty list, return the starting value acc.
    • 
  
  • foldl: “update the accumulator with x, then continue with the rest”:
    foldl f (f acc x) xs. The type: (b -> a -> b) -> b -> [a] -> b
    — f takes acc first, element second.
    • 
  
  • foldr: “combine x with the result for the rest”: f x (foldr f acc xs). The type:
    (a -> b -> b) -> b -> [a] -> b — f takes element first, acc second.
    • 





Where they differ — subtraction (not commutative):


foldl (-) 0 [1,2,3]
foldr (-) 0 [1,2,3]




foldl (-) 0 [1,2,3]foldr (-) 0 [1,2,3]


= foldl (-) (0-1) [2,3]
= foldl (-) ((0-1)-2) [3]
= foldl (-) (((0-1)-2)-3) []
= ((0-1)-2)-3 = -6		
= 1 - foldr (-) 0 [2,3]
= 1 - (2 - foldr (-) 0 [3])
= 1 - (2 - (3 - foldr (-) 0 []))
= 1 - (2 - (3 - 0)) = 2

The Haskell mistakes that cost points

    
  
  • No type signature — write it first; it forces you to know what goes in and out.
    • 
  
  • Forgetting the base case f [] = ... (the function crashes on the empty list).
    • 
  
  • Writing x ++ xs when x is an element — use x : xs; ++ needs two
    lists ([x] ++ xs).
    • 
  
  • f x:xs means (f x) : xs. In patterns always write parentheses: f (x:xs).
    • 
  
  • foldl’s function takes acc first; foldr’s takes the element first. Getting it backwards is a type
    error (or a wrong answer).
    • 
  
  • Indentation: the lines under where must line up.
