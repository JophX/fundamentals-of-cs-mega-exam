4. Encapsulation and information hiding — not vague this time

The idea in plain words

Think of a medicine capsule. Encapsulation is putting the ingredients together in one capsule: the data and the operations that work on it are packed into one unit (a class, a module, an ADT). Information hiding is making the capsule opaque: from outside you can’t see or touch what is inside; you can only use it the intended way (swallow it = call its public operations).

They are two different things. You can have a capsule you can see through: a Python class groups data and methods (encapsulation) but anyone can still write s.data = [] (no real hiding).

4.1 Definitions (these are the lecture’s own words, expanded)

Encapsulation

An abstract data type is specified as one syntactic unit (class, module, package) that contains the representation of the data together with the operations on it. Other parts of the program can use the type only through that definition.

Advantages: better organisation (everything about stacks is in one place), code is easier to read and understand, easier to modify and maintain, and units can be compiled separately.

Information hiding

The internal representation of the unit (its data fields, helper functions, implementation details) is not accessible from outside the unit. Clients see only the interface (the public operations and their types).

Advantages: reliability — code that is not “authorised” cannot read or change the internal data, so the unit can guarantee its own invariants (e.g. top always points at the top element). And changeability — the representation can be replaced (array → linked list) without changing any client code, because no client could depend on it. It also lowers what a programmer must know to use the unit.

How languages provide it: access modifiers private/protected/public (Java, C++, C#); separate definition and implementation modules (Modula-2: the definition module is public, the implementation module is hidden); export lists (Haskell modules exporting a type but not its constructor; ML abstype).

Model answer: “Explain encapsulation” (write all four parts)

(1) Definition. Encapsulation means that a data type’s representation and the operations on it are defined
together as one syntactic unit (a class, module or package), so the rest of the program uses the type only through that
unit’s definition. (2) Purpose. It is a way of achieving data abstraction: the user thinks in terms of “a stack
with push/pop”, not in terms of arrays and indices. (3) Example. A class Stack containing the array
and the top index together with push, pop, isEmpty.
(4) Advantages. Better organisation of the code, easier to read, understand and modify, and supports separate
compilation of the unit. It is often combined with, but is not the same as, information hiding.





Model answer: “Explain information hiding” (write all five parts)

(1) Definition. Information hiding means that the internal representation and implementation details of a unit
are not visible or accessible outside it; clients can only use the public interface. (2) Mechanism. E.g.
private fields with public methods in Java/C++, an export list in a Haskell module that exports the
type but not its constructors, or Modula-2’s separate definition and implementation modules. (3) Example. In the
stack class, data and top are private; s.top = 50 from outside is a compile error,
so nobody can put the stack into an inconsistent state. (4) Advantages. Reliability/integrity (invariants cannot be
broken by outside code), the implementation can be changed without affecting clients (low coupling), and users need to know
less. (5) Relation to encapsulation. Encapsulation groups data and operations; information hiding
restricts access to the grouped internals. Together they give an abstract data type.
(Possible disadvantage to mention: some overhead — calls to getters/setters — and sometimes less flexibility, e.g. a
subclass or a trusted piece of code may legitimately need internal access; that is why languages add protected
or “friend”.)

Why your answer was “too vague”

“Encapsulation is hiding the data” is (a) vague and (b) mixes up the two concepts. Examiners want: a precise
definition, the mechanism, an example, the advantages, and the difference from the related concept. The model answers above
have exactly that structure — use it for every “explain the concept X” question.
