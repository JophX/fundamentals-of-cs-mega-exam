5. Staying regular: closure properties FCS

Suppose you have two regular languages — two things you can recognise with sticky-note machines. You combine them: their union, their intersection, one after the other, the complement. Is the result still something a sticky-note machine can recognise?

If the answer is always yes, we say regular languages are closed under that operation. It’s like asking: “if I add two whole numbers, do I always get a whole number?” (yes — closed). “If I divide them?” (no — 1/2).

How do you prove “always yes”?

You can’t test all languages. Instead you give a recipe: “give me machines (or regexes) for \(L_1\) and \(L_2\), and here is how I build one for the result.” If the recipe always works, you’ve proven closure. Every proof in this chapter is a recipe you already know.

5.1 The four operations the exam asks about

Union and concatenation — use regexes. If \(r_1\) and \(r_2\) describe \(L_1\) and \(L_2\), then \(r_1+r_2\) describes the union and \(r_1r_2\) describes the concatenation. Done — a regex exists, so the language is regular. (Star works the same way: \(r_1^*\).)

Complement — flip the verdict. Take a DFA for \(L\). Run it exactly as before, but swap which states are accepting. Every string that used to be accepted is now rejected and vice versa. That machine recognises \(\overline L\).

This only works with a complete DFA

With an NFA, swapping fails: a string might have one path ending in an accepting state and another ending in a non-accepting state, so it would be accepted both before and after swapping. And the DFA must have all its arrows (include the trap state!), or strings that fell off a missing arrow would be rejected both times.

Intersection — run both machines side by side. The product construction from Chapter 2: states are pairs, accept when both accept. (Or a slicker argument: \(L_1\cap L_2=\overline{\overline{L_1}\cup\overline{L_2}}\) by De Morgan’s law — and we already have complement and union.)

Exam: “Argue that regular languages are closed under complement, intersection, concatenation and union” (5 p)

Let \(L_1,L_2\) be regular, described by regular expressions \(r_1,r_2\) and recognised by complete DFAs \(M_1=(Q_1,\Sigma,\delta_1,q_1,F_1)\), \(M_2=(Q_2,\Sigma,\delta_2,q_2,F_2)\).

Union / concatenation: \(r_1+r_2\) and \(r_1r_2\) are regular expressions for \(L_1\cup L_2\) and \(L_1L_2\), so these are regular.

Complement: \((Q_1,\Sigma,\delta_1,q_1,Q_1\setminus F_1)\) follows the same path as \(M_1\) on every input but accepts exactly when \(M_1\) rejects, so it recognises \(\overline{L_1}\). (\(M_1\) must be complete — add a trap state if needed.)

Intersection: the product DFA \((Q_1\times Q_2,\Sigma,\delta,(q_1,q_2),F_1\times F_2)\) with \(\delta((p,q),a)=(\delta_1(p,a),\delta_2(q,a))\) simulates both machines at once and accepts exactly when both accept, i.e. it recognises \(L_1\cap L_2\).

Also closed: difference (\(L_1\cap\overline{L_2}\)) and reversal (turn all arrows around).

5.2 True/false questions: think of extreme examples

The FCS exam has true/false questions where a wrong answer costs half a point. The trick for any statement with “necessarily” or “always”: to show it’s false, you need just one counterexample — and the best counterexamples are the extreme languages: \(\emptyset\) (nothing) and \(\Sigma^*\) (everything).

StatementAnswer and the example that settles it
\(L\) context-free but not regular, \(L'\) regular ⇒ \(L\cup L'\) is not regularFalse: take \(L'=\Sigma^*\). The union is everything — regular.
…same, ⇒ \(L\cap L'\) is not regularFalse: take \(L'=\emptyset\). The intersection is empty — regular.
Every finite language is regularTrue: list its strings joined by \(+\).
Every subset of a regular language is regularFalse: \(\{a^nb^n\}\subseteq\Sigma^*\).

5.3 Questions a machine can always answer

For regular languages, these questions all have algorithms (they are decidable):

  • Is \(w\) in \(L\)? Run the DFA.
  • Is \(L\) empty? Can you reach any accepting state from the start? (Follow the arrows.)
  • Is \(L\) infinite? Is there a loop on some path from the start to an accepting state? A loop means you can go round it as often as you like and still accept — infinitely many strings.
  • Are \(L_1\) and \(L_2\) equal? Minimise both DFAs and compare (Chapter 4).

5.4 The ☆ question: an infinite union

We know: union of two regular languages is regular. So union of three is too, and of a hundred. What about an infinite union? It’s tempting to say “yes, obviously” — and that’s exactly the trap.

Exam ☆: “Each \(L_n\) is regular. Is \(\bigcup_{n\in N} L_n\) necessarily regular?”

No. Let \(L_n=\{a^nb^n\}\) — a language with a single string, so it’s finite and therefore regular. But the union of all of them is \(\{a^nb^n\mid n\ge0\}\), which is not regular (Chapter 6). Closure under union only covers finitely many languages.
