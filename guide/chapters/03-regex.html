3. Regular expressions BOTH

Intuition

A regular expression is a formula that describes a language, built from single letters using three operations: or (union), then (concatenation) and repeat (star). A DFA is a machine that checks strings; a regular expression is a pattern that describes them. They have exactly the same power (Kleene’s theorem).

3.1 Definition (course syntax)

Definition (Linz)
  1. \(\emptyset\), \(\lambda\) and every \(a\in\Sigma\) are regular expressions (primitive). They denote \(\emptyset\), \(\{\lambda\}\) and \(\{a\}\).
  2. If \(r_1, r_2\) are regular expressions, so are \(r_1 + r_2\) (union), \(r_1 \cdot r_2\) or just \(r_1r_2\) (concatenation), \(r_1^*\) (star) and \((r_1)\).
  3. Nothing else is a regular expression.

\(L(r_1+r_2) = L(r_1)\cup L(r_2)\), \(L(r_1r_2) = L(r_1)L(r_2)\), \(L(r^*) = (L(r))^*\).

+ means different things in different places

In the course (Linz), \(a+b\) means “\(a\) or \(b\)”. In programming regexes (Python, Java, grep) the “or” is written a|b and a+ means “one or more a’s” (\(aa^*\)). Sipser writes \(\cup\) for union. On the FCS exam use the course notation; on the PL exam either is fine if you say which.

Precedence: star, then concatenation, then union

Exactly like arithmetic where \(^\wedge\) binds tighter than \(\times\), which binds tighter than \(+\):

Regexmeansnot
\(ab^*\)\(a(b^*)\): \(a, ab, abb,\dots\)\((ab)^*\)
\(a+bc\)\(a+(bc)\): \(\{a, bc\}\)\((a+b)c\)
\(a+b^*\)\(a+(b^*)\)\((a+b)^*\)

This is a first taste of precedence, the topic of PL exam Problem 3 (Chapter 8).

3.2 Reading regular expressions

Read from the outside in, and list the shortest members first.

\((a+b)^*aba(a+b)^*\)contains \(aba\) somewhere (“anything, aba, anything”)

3.3 Writing regular expressions — recipes

Recipe: building a regex
  • “contains X” → \((a+b)^*\,X\,(a+b)^*\).
  • “starts with X” / “ends with X” → \(X(a+b)^*\) / \((a+b)^*X\).
  • “exactly / at most k of letter b” → put the b’s explicitly with \(a^*\) (all the other letters, starred) between them: exactly two b’s = \(a^*ba^*ba^*\).
  • Counting modulo k (“even number of b’s”, “#a divisible by 3”) → a block that contains exactly k of the counted letter, starred, with the other letters starred in between: \(b^*(ab^*ab^*ab^*)^*\).
  • “A or B or C” → build each separately, join with \(+\).
  • Forbidden pattern (“no aa”) → describe what every letter must be followed by, and fix the end.

The FCS 2022 exam, Q1 statement 1: “strings over \(\{a,b,c\}\) that start with \(a\), or end with \(c\), or contain an odd number of \(b\)’s — is this regular?” True. Each part is regular and regular languages are closed under union. You can even write the regex: \[a(a+b+c)^* \;+\; (a+b+c)^*c \;+\; (a+c)^*b(a+c)^*\big(b(a+c)^*b(a+c)^*\big)^*\]

3.4 Useful identities

\(r+r = r\)union with itself
\(\lambda r = r\lambda = r\)λ is the unit of concatenation

\((r^*)^* = r^*\), \(r^*r^* = r^*\)repeating a repeat adds nothing
\(\lambda + rr^* = r^*\)“zero times, or at least once”
\((a+b)^* = (a^*b^*)^*\)both are “everything”
\((ab)^*a = a(ba)^*\)both are \(a, aba, ababa,\dots\)
\((a+b)^* \ne a^*+b^*\) !\(ab\) is in the left one only

3.5 Regular expression → NFA (Thompson’s construction)

Intuition

Build a small NFA for each piece, then glue with λ-arrows, following the structure of the expression — exactly like evaluating an arithmetic expression bottom-up. Each little NFA has one start and one final state.

digraph{rankdir=LR; node[shape=circle fontname="Helvetica" width=0.35 label=""]; edge[fontname="Helvetica"]; compound=true; subgraph cluster_a{label="a" fontname="Helvetica"; a1->a2[label="a"]; a2[shape=doublecircle];} subgraph cluster_u{label="r1 + r2" fontname="Helvetica"; u0; u1[shape=box label="r1"]; u2[shape=box label="r2"]; uf[shape=doublecircle]; u0->u1[label="λ"]; u0->u2[label="λ"]; u1->uf[label="λ"]; u2->uf[label="λ"];} subgraph cluster_c{label="r1 r2" fontname="Helvetica"; c1[shape=box label="r1"]; c2[shape=box label="r2"]; c1->c2[label="λ"];} subgraph cluster_s{label="r*" fontname="Helvetica"; s0; s1[shape=box label="r"]; sf[shape=doublecircle]; s0->s1[label="λ"]; s1->sf[label="λ"]; s0->sf[label="λ"]; sf->s0[label="λ"];} }

In words: union — new start with λ-arrows into both machines, both finals λ-arrow to a new final. Concatenation — λ-arrow from the final of \(r_1\) to the start of \(r_2\). Star — new start that can skip straight to the end (zero repetitions) and a λ-arrow back to repeat.

Example: \((a+b)^*ab\). Build \(a+b\) (union of two letter-machines), star it, then concatenate with \(a\) and then \(b\). If you then remove the unnecessary λ’s you get exactly the 3-state NFA of Chapter 2 (\(p_0\) loops on \(a,b\), then \(a\), then \(b\)).

3.6 Automaton → regular expression (state elimination)

Recipe: state elimination (the idea)
  1. Add a new start state with a λ-arrow to the old start, and a new single final state with λ-arrows from all old finals.
  2. Remove the other states one at a time. When you remove state \(q\) that has a self-loop \(s\), an incoming arrow \(p \xrightarrow{r_1} q\) and an outgoing arrow \(q\xrightarrow{r_2} t\), add the arrow \(p \xrightarrow{r_1 s^* r_2} t\) (union it with an existing \(p\to t\) arrow using \(+\)).
  3. When only start and final remain, the label on the arrow is the regex.

You do not need to be fast at this for the exam; you need to know that it works, because it proves:

Theorem (Kleene)

A language is regular ⇔ it is accepted by some DFA ⇔ by some NFA ⇔ it is described by some regular expression ⇔ it is generated by a right-linear (regular) grammar (rules of the form \(A\to aB\) or \(A\to a\) or \(A\to\lambda\)).

3.7 Regular expressions in real programming languages PL

Practical regex libraries add shorthand, but most of it is just abbreviation of the three basic operations:

Practical syntaxMeaningCourse notation
a|ba or b\(a+b\)
a*zero or more\(a^*\)
a+one or more\(aa^*\)
a?optional\(\lambda + a\)
[a-z]one character in the range\(a+b+\dots+z\)
.any single characterunion of the whole alphabet
a{2,3}2 or 3 a’s\(aa(\lambda+a)\)

A scanner/lexer describes each kind of token by a regex, e.g. identifier [a-zA-Z_][a-zA-Z_0-9]*, integer [0-9]+, and runs the corresponding finite automaton (Chapter 22). Caution: some library features, notably back-references like (a*)b\1 (“the same group again”), go beyond regular languages — \(\{a^nba^n\}\) is not regular, yet (a*)b\1 matches exactly it. So “regex” in a library is not always “regular” in theory.
