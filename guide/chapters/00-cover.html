How to use this guide (read this first)

You have two exams with one day in between. They overlap a lot: grammars, regular expressions and the idea of “a language as a set of strings” show up in both. So this guide is built as one course, not two:

  1. Part I — The shared foundation BOTH. Strings and languages, automata, regular expressions, context-free grammars, precedence & associativity, parsing. You need this for both exams, so it comes first.
  2. Part II — Computability & complexity FCS. Turing machines, decidability, the halting problem, P and NP.
  3. Part III — Haskell from zero PL. Written as if you have never seen it. Ends with every kind of function the exam has asked you to write.
  4. Part IV — Programming-language concepts PL. Abstraction, encapsulation, polymorphism, scope, binding, parameter passing, interpreters, concurrency, exceptions, logic programming — with model answers written the way an examiner wants to read them.
  5. Part V — Real exams, solved, and new practice exams with solutions.
  6. Appendix — one-page cheat sheets and a Swedish–English glossary (the PL exam is in Swedish).
How each chapter works

Every chapter goes: intuition first (what is this, in plain words) → the formal definition (what you write on the exam) → worked examples (slowly, every step shown) → recipes (a checklist you can follow under stress) → traps (where students lose points) → practice with solutions.

The coloured boxes mean: Intuition, Definition, Theorem, Recipe, Exam tip / Model answer, Trap.

The course changed in 2024

The official syllabus for 5DV086 was revised from 2024-01-01. The listed literature is now Crafting Interpreters (Robert Nystrom) and Learn You a Haskell for Great Good! (Lipovača). The content description is unchanged: variables, binding, scope, types, type checking, control abstraction, subprograms, parameter passing, abstract data types, the paradigms (imperative, OO, functional, logic), concurrency and exceptions, with special emphasis on functional programming (recursive functions, recursive data types, type constructors). Because of the new book, expect more weight on how interpreters work (scanning, parsing, trees, environments) — Chapter 22 covers it and includes a small working interpreter in Haskell. When you find your own recent exams, compare them against the table above.

Why you lost points before — and how to stop
  • Blank answers get zero. Every question in both exams gives partial credit. Write the definition, the recipe, the first steps. “Motivate” means: say why, in one sentence per step.
  • Grammar questions: test your grammar on 3–4 short strings (including the empty string!) before moving on. Chapter 7 shows exactly how.
  • Haskell questions: always write the type signature first; always write the base case first. Then trace your function on a tiny input on paper.
  • Theory questions: define the term, give a tiny example, give one advantage and one disadvantage. That structure alone earns most of the points.
