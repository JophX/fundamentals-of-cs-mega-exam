12. Turing machines FCS

Our door-keeper started with sticky notes (finite automata), then got a stack of plates (pushdown automata). Each upgrade let them recognise more. Now let’s go all the way. Give them an endless notebook: they can write anywhere, erase, flip back and forth, reread. That’s a Turing machine — and here is the astonishing part: no further upgrade helps. Everything any computer can compute, a Turing machine can compute. Your laptop is, in theory, just a fast Turing machine.

12.1 How it works

The picture

An infinite tape of cells. Your input is written on it, blanks (\(\square\)) everywhere else. A head sits on one cell. At each step, looking only at its current state and the symbol under the head, the machine: writes a symbol, moves one cell left or right, and changes state. When there is no rule for the current situation, it halts. If it halts in an accepting state, the input is accepted.

Two big differences from before: it can go back, and it might never stop.

Definition (on your exam sheet)

\(M=(Q,\Sigma,\Gamma,\delta,q_0,\square,F)\) with tape alphabet \(\Gamma\supseteq\Sigma\cup\{\square\}\) and \(\delta:Q\times\Gamma\to Q\times\Gamma\times\{L,R\}\). \(\delta(q,a)=(p,b,R)\) means: in state \(q\) reading \(a\), write \(b\), move right, go to state \(p\).

12.2 Watching one work: \(a^nb^n\)

A stack machine did this by counting. A Turing machine does it the way you’d do it with a pencil: cross off an \(a\), run over to the first uncrossed \(b\), cross it off, run back, repeat. If everything gets crossed off in pairs, accept.

12.4 Upgrades that don’t upgrade


People have tried to make Turing machines stronger: more tapes, a 2-D tape, a “stay” move, guessing. None of it lets you compute
anything new — each can be simulated by the plain machine (usually more slowly). Two tapes? Put them on one tape as two
tracks, and mark where each head is. The exam asks about the most interesting one:



Exam (6 p): why nondeterministic TMs are no more powerful than deterministic ones

A deterministic TM is a special NTM, so NTMs are at least as powerful. For the other direction, let \(N\) be an NTM. On input
\(w\), all possible computations of \(N\) form a tree: each node is a configuration, and its children are the configurations
reachable in one step (at most \(k\) of them, since \(\delta\) offers finitely many choices). \(N\) accepts iff some node is an accepting
configuration.


A deterministic machine \(D\) searches this tree breadth-first: for \(\ell=1,2,3,\dots\) it tries every sequence of at most \(\ell\)
choices, simulating \(N\) along it (convenient with three tapes: input, work, current choice sequence; and multitape machines equal
single-tape ones). If \(N\) has an accepting computation of length \(\ell\), \(D\) finds it at round \(\ell\) and accepts; otherwise \(D\) never
accepts. Breadth-first matters: depth-first could get lost forever in one infinite branch. So \(L(D)=L(N)\) — same power, though the
simulation can take exponentially longer.





12.5 The universal machine


A Turing machine is described by a finite list of rules, which can be written as a string. So one machine, \(U\), can take
another machine’s description plus an input, and simulate it. That’s a universal Turing machine — it’s the idea of a
computer that runs programs, invented before computers existed. It also means: there are only countably many Turing machines
(they’re strings). Keep that in mind for the next chapter.
