20. Control flow and subprograms PL

20.1 The minimum you need to compute anything

Here’s a surprising fact. An imperative language that has only assignment (x = expression) can’t compute much. Add just two things — a way to choose (if) and a way to jump (goto) — and it can compute anything a Turing machine can. Everything else — while, for, switch — is there to make programs readable, because raw goto turns code into spaghetti.

  • Choosing: if-then-else (use blocks { } — otherwise nested ifs are ambiguous, the “dangling else”), switch/case (in C you need break, or execution falls through to the next case), and pattern matching in Haskell.
  • Repeating: while checks first; do … while runs the body at least once. break leaves the loop, continue skips to the next round. Iterators (for fruit in basket) loop over a collection without an index — simpler and harder to get wrong.
  • Guarded commands are an unusual, elegant idea: you list several (condition → action) pairs, and any one whose condition is true may be chosen. A loop of them keeps going until no condition holds. Example: “while some neighbours are in the wrong order, swap them” — it sorts, whatever order you pick the swaps in. The point is to express only what matters for correctness.

20.2 Subprograms: abstraction for actions

A subprogram (function, procedure, method) lets you give a name to a piece of work and reuse it — so you think “sort the list”, not the twenty lines that do it. That’s process abstraction, the partner of the data abstraction in Chapter 21. Small vocabulary: a procedure does something (changes state), a function returns a value, a method belongs to an object.

Every call pushes an activation record onto the stack — the return address, the parameters and the local variables — and pops it at return. That’s why a recursive function can call itself a thousand times without the calls trampling each other: each has its own record.

Language designers must decide lots of things about subprograms: How are argument types checked? Can functions be nested inside functions? Can a function be passed as an argument (as in Haskell’s map)? Can two functions share a name if their parameter types differ (overloading)? Can one definition work for many types (generics)? May functions have side effects? How many values can they return?
