13. Decidability, countability, the halting problem FCS

13.1 Recursive vs recursively enumerable

Definitions
  • \(L\) is recursively enumerable (RE) if some TM accepts exactly \(L\): on \(w\in L\) it halts and accepts; on \(w\notin L\) it rejects or runs forever. (A recognizer.)
  • \(L\) is recursive (decidable) if some TM accepts \(L\) and halts on every input. (A decider.)
  • A problem is decidable if the language of its yes-instances is recursive.
Key facts
  • Recursive ⊂ RE (strict). Recursive languages are closed under complement (swap accept/reject of the decider).
  • If \(L\) and \(\overline L\) are both RE, then \(L\) is recursive: run both recognizers in parallel (one step each); one of them must accept.
  • So \(\overline H\) (the complement of the halting problem) is not RE.
FCS Q1 true/false traps
  • “It can be correct to say that a Turing machine M is decidable.” — False. Languages/problems are decidable; a machine is a decider (halts always) or not. (Expected answer: false.)
  • “The set of suitably encoded Turing machines is RE.” — True (even recursive: a TM can check whether a string is a valid encoding).

13.2 Countability and diagonalization

Intuition

There are only countably many TMs (each is a finite string, and strings can be listed by length). But there are uncountably many languages (all subsets of \(\Sigma^*\)). So most languages have no TM at all.

Cantor: \(2^{\Sigma^*}\) is uncountable

Suppose the languages could be listed \(L_1,L_2,L_3,\dots\) and list the strings \(w_1,w_2,w_3,\dots\). Define \(D=\{w_i\mid w_i\notin L_i\}\). For each \(i\), \(D\) differs from \(L_i\) on the string \(w_i\) (flip the diagonal). So \(D\) is not in the list — contradiction. Hence there are languages that are not RE.

13.3 The halting problem

Theorem

\(H=\{\langle M\rangle w \mid M \text{ halts on } w\}\) is RE but not recursive.

RE: the universal TM simulates \(M\) on \(w\) and accepts if it halts.

Not recursive (proof by contradiction): suppose a TM \(H_D\) decides it. Build \(D\): on input \(\langle M\rangle\), run \(H_D\) on \(\langle M\rangle\langle M\rangle\); if it says “halts”, loop forever; if it says “doesn’t halt”, halt. Now run \(D\) on \(\langle D\rangle\): \(D\) halts ⇔ \(H_D\) says \(D\) doesn’t halt on \(\langle D\rangle\) ⇔ \(D\) doesn’t halt. Contradiction. So no such \(H_D\).

13.4 Reductions

Recipe: proving problem B is undecidable
  1. Pick a known undecidable problem A (usually halting).
  2. Assume B is decidable by a decider \(M_B\).
  3. Show how to use \(M_B\) to decide A: given an instance of A, construct (by an algorithm that always halts) an instance of B whose answer is the same.
  4. Then A would be decidable — contradiction.

Direction matters: reduce the known hard problem to the new one.

Example: the state-entry problem

“Given \(M\), \(w\), and a state \(q\): does \(M\) ever enter \(q\) on \(w\)?” Reduce halting: given \(\langle M\rangle, w\), build \(M'\): add a new state \(q_{new}\); wherever \(M\) would halt (\(\delta(p,a)\) undefined), make \(M'\) go to \(q_{new}\). Then \(M'\) enters \(q_{new}\) on \(w\) ⇔ \(M\) halts on \(w\). A decider for state-entry would decide halting. So state-entry is undecidable.

Example: blank-tape halting

Given \(M, w\), build \(M_w\): starting on a blank tape, it first writes \(w\), then runs \(M\). \(M_w\) halts on blank ⇔ \(M\) halts on \(w\). So blank-tape halting is undecidable.

Rice’s theorem (general version): every non-trivial property of the language of a TM (“is \(L(M)\) empty?”, “finite?”, “regular?”) is undecidable.
