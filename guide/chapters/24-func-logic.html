24. Functional and logic languages PL

24.1 Functional languages

Family: LISP → Scheme, ML, Haskell, Erlang. Defining feature: no side effects — a function’s result depends only on its arguments. The lecture’s member in two languages:

; Scheme
(DEFINE (member a lst)
  (COND ((NULL? lst) '())
        ((EQ? a (CAR lst)) #T)
        (ELSE (member a (CDR lst)))))

(* ML *)
fun member a []      = false
  | member a (b::l)  = a = b orelse member a l

In Haskell: member a [] = False; member a (b:l) = a == b || member a l. Haskell is purely functional, handles I/O in a controlled way, and has non-strict (lazy) semantics: squares = [n*n | n <- [0..]] is an infinite list that is only computed as far as needed.

Advantages (slide)

Programs are easier to prove correct and to transform (referential transparency); functions are first-class citizens; simpler syntax and semantics; natural for many problems; easy to parallelise (no shared state). Disadvantages: less efficient on conventional hardware, I/O and state are awkward, unfamiliar. Many imperative languages have adopted functional features: lambdas / functions as parameters in Java, JavaScript, Python, Ruby, C#.

24.2 Logic programming (Prolog)

Intuition

You don’t tell the computer how to solve the problem. You state facts and rules about the problem domain, then ask whether a goal follows. A built-in proof engine searches for an answer (by unification and backtracking). Example: “a sorted list is a permutation of the old list in which every element is ≤ the next” — that’s the whole sort program.



Queries (run in SWI-Prolog): “What does charlie study?”, “Who are kirke’s students?”, “Who teaches jack?”




To answer professor(kirke, S): find teaches(kirke, C) → C = csc135; then
studies(S, csc135) → S = charlie, and on backtracking S = olivia. Matching patterns with
variables is unification; trying the next alternative when one fails is backtracking.


Limitations (slide): efficiency (blind search can be very slow); the programmer must still think about the search order
(order of rules matters, left recursion can loop forever); answers are only true/fail; negation is “not provable” (closed-world
assumption), not logical negation. The cut ! partly controls the search (stop backtracking). Applications:
databases, expert systems, AI, natural language.
