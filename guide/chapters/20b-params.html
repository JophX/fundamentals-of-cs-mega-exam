20.3 Parameter passing: by value, by reference and the others

The idea in plain words

By value = you give the function a photocopy. It can scribble on the copy; your original is untouched. By reference = you give the function the address of your original. Whatever it writes, it writes on your original.

20.3.1 Vocabulary first

  • Formal parameter: the name in the function definition (x in void f(int x)).
  • Actual parameter (argument): the expression in the call (a+1 in f(a+1)).
  • Modes (semantic models): in (data goes into the function), out (data comes back to the caller), in-out (both).
  • Implementation: essentially either copy the value or pass an access path (address).

20.3.2 The five methods

MethodModeHow it worksProblems
By valueinThe value of the actual parameter is copied into the formal parameter, which acts as a local variable. Changes inside do not affect the caller.Copying large data (arrays, structs) costs time and memory.
By resultoutNo value is passed in. At return, the formal parameter’s final value is copied back to the actual parameter (which must be a variable).procA(a, a): two results copied to the same variable — the order of copying decides the value. procA(a[i], i): is the address of a[i] computed at the call or at the return?
By value-result (copy-in/copy-out)in-outCopied in at the call and copied back at the return.Same aliasing/order problems as by result; copying cost twice. procA(4+4): an expression cannot receive a result.
By referencein-outThe address of the actual parameter is passed. The formal parameter is an alias of the caller’s variable; every read and write goes to the original.Aliasing (two names for one variable: f(a, a)); unwanted side effects “open up” the caller’s data; indirect access is slightly slower.
By namein-outThe argument expression is passed unevaluated and re-evaluated every time the parameter is used (like textual substitution; Algol 60).Hard to understand and slow; basis for lazy evaluation (Haskell uses call-by-need).

Model answer: “Explain the differences between pass-by-value and pass-by-reference. Advantages and disadvantages?” (6 p)

Pass-by-value: at the call, the value of the actual parameter is evaluated and copied into the
formal parameter, which then behaves like a local variable. Changes to it inside the subprogram do not affect the caller
(in-mode). Advantages: safe — no side effects on the caller’s variables, easy to reason about; the argument can be
any expression (f(a+1)); access to the parameter is fast (local). Disadvantages: copying large objects
costs time and memory; it cannot be used to return results through parameters.


Pass-by-reference: the address of the actual parameter is passed, so the formal parameter is an
alias for the caller’s variable; all reads and writes go directly to the original (in-out mode). Advantages:
efficient — no copying, only an address is passed, even for large structures; the subprogram can return results through
parameters (e.g. swap(a, b)). Disadvantages: side effects — the caller’s data can be changed
unintentionally; aliasing (e.g. f(a, a), or an array element and the whole array) makes programs hard
to understand and verify; each access goes through an indirection (slightly slower); the argument must be a variable,
not an arbitrary expression.


Example: swap(a, b) works only with pass-by-reference; with pass-by-value it swaps the copies and
a, b are unchanged. (Java passes everything by value, but for objects the value is a
reference — so the object can be modified, but the caller’s variable cannot be made to point elsewhere.)
