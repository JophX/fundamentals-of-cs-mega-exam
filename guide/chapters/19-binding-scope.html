19.2 Variables and binding

A variable has six attributes

name, address (where in memory), value, type, lifetime (when it exists in memory), scope (where in the program text it can be used).

Binding and binding time

A binding is an association between a name and something (a value, a type, an address, an operation). Binding time is when it happens: language design (* means multiplication), implementation (size of int), compile time (type of a variable in Java), load time (address of a static variable), run time (value of a variable; address of a local). Static binding = before run time and doesn’t change; dynamic = during run time or can change.

19.3 “Variables” in functional vs imperative languages (2023-05-05 Problem 5, 6 p)

Model answer: why is a = b + 4 “assignment” in imperative languages but “naming/binding a value” in functional ones?

In an imperative language a variable is an abstraction of a memory cell: a = b + 4 evaluates b + 4 and stores the result in the cell named a, overwriting the previous contents. The value of a can change later (a = a + 1 is meaningful), so the meaning of a depends on when you look — the program has state and assignment is a side effect.

In a pure functional language there is no mutable state: a = b + 4 is a definition — it binds the name a to the value of b + 4, like in mathematics, and that binding can never change within its scope. a = a + 1 is not an update but a (recursive, non-terminating) definition. Because names always stand for the same value, any occurrence of a can be replaced by its value (referential transparency), which makes programs easier to reason about, test, parallelise and transform. Repetition is expressed by recursion instead of by changing loop variables. The difference is thus mutable storage location vs immutable name for a value.

19.4 Scope

Definitions
  • Scope: the part of the program text where a name is visible. Lifetime: the time during execution when the variable exists. They differ: a C static local has local scope but lives for the whole run.
  • Static (lexical) scope: a free name refers to the declaration in the nearest enclosing block in the program text. Decided at compile time. (Almost all languages: C, Java, Python, Haskell.)
  • Dynamic scope: a free name refers to the most recent binding in the chain of active calls at run time. (Early Lisp, bash, Perl’s local.)
  • Block structure: blocks can be nested, and inner declarations shadow outer ones with the same name.
