2. The weakest machine: finite automata BOTH

Imagine you work at a door. People hand you a paper strip with letters on it, and you read the letters one at a time, left to right, and you can never go back. At the end you must say “let them in” or “no”. The catch: you have no paper to write on. All you have is a small number of sticky notes, and at any moment exactly one of them is on your forehead, reminding you of where you are.

That is a finite automaton. The sticky notes are its states. And the entire skill of designing one comes down to a single question — the most important question in this chapter:

“What is the smallest thing I need to remember about what I’ve read so far?”

2.1 Your first machine

Job: let a string in if it has an even number of b’s.

What do you need to remember? Not the whole string. Not even how many b’s — just whether the count so far is even or odd. Two sticky notes: E and O. You start at E (zero b’s is even). An a changes nothing. A b flips you.

digraph{rankdir=LR; node[shape=circle fontname="Helvetica"]; edge[fontname="Helvetica"]; s[shape=point]; E[shape=doublecircle]; s->E; E->E[label="a"]; E->O[label="b"]; O->E[label="b"]; O->O[label="a"];}

Let’s walk \(abba\) through it: start E → a → E → b → O → b → E → a → E. We end on E, a double circle: accepted. Now try \(ab\) yourself — you should end on O and reject.

That drawing is the machine. On the exam you describe it formally like this:

Definition — DFA (deterministic finite automaton)

\(M=(Q,\Sigma,\delta,q_0,F)\): \(Q\) the finite set of states (sticky notes), \(\Sigma\) the alphabet, \(\delta:Q\times\Sigma\to Q\) the transition function (“in this state, reading this letter, go there”), \(q_0\) the start state, \(F\subseteq Q\) the accepting states. The language of \(M\) is the set of strings that lead from \(q_0\) to a state in \(F\).

Deterministic means there is exactly one arrow for every state and every letter — never a choice, never a missing arrow.

“Never a missing arrow” — what if some letter should just kill the string? Then you add a trap state: a non-accepting state that loops to itself on everything. Once you fall in, you never get out. (Many drawings leave the trap state out and say “missing arrows go to the trap” — that’s fine if you say it.)

2.2 Getting better at it: remembering the end of the string

Job: accept strings that end with ab.

What do I need to remember? How much of “ab” I’ve just seen:

  • \(q_0\): nothing useful yet (the string doesn’t end in a or ab),
  • \(q_1\): I just saw an a — half-way there,
  • \(q_2\): I just saw ab — if the string stopped now, accept.
digraph{rankdir=LR; node[shape=circle fontname="Helvetica"]; edge[fontname="Helvetica"]; s[shape=point]; q2[shape=doublecircle]; s->q0; q0->q0[label="b"]; q0->q1[label="a"]; q1->q1[label="a"]; q1->q2[label="b"]; q2->q1[label="a"]; q2->q0[label="b"];}

The interesting arrows are the ones that “fall back”. Suppose we’re in \(q_2\) (just saw ab) and read an a. Is all hope lost? No! The string now ends in a — we’re half-way again, so we go to \(q_1\), not \(q_0\). And from \(q_1\), another a keeps us in \(q_1\): aa still ends in a. Getting those fall-back arrows right is where most DFA points are won or lost. Always ask: “after this letter, what does the string end with?”

One more: “contains aba somewhere”

digraph{rankdir=LR; node[shape=circle fontname="Helvetica"]; edge[fontname="Helvetica"]; s[shape=point]; q3[shape=doublecircle]; s->q0; q0->q0[label="b"]; q0->q1[label="a"]; q1->q1[label="a"]; q1->q2[label="b"]; q2->q3[label="a"]; q2->q0[label="b"]; q3->q3[label="a,b"];}

Same idea, with one new twist: once you’ve seen aba, the answer is yes forever, whatever comes after. So \(q_3\) just loops. That’s a “success trap”.

Recipe: designing a DFA
  1. Ask “what must I remember?” — a parity, a remainder, the last few letters, a flag “already seen X”.
  2. One state per thing-to-remember. Accepting = “if the input stopped now, I’d say yes”.
  3. For every state and every letter, ask “what do I remember now?” and draw that arrow.
  4. Is \(\lambda\) in the language? Then the start state must be accepting.
  5. Test on 3–4 short strings.

2.3 The limit: what sticky notes can’t do

Try to build a DFA for \(\{a^nb^n\}\) — some a’s, then exactly as many b’s. You’d need to remember how many a’s you saw: 1, 2, 3, … 1000, … — one sticky note per number, and there’s no end to the numbers. But a DFA has a fixed, finite number of notes. So it can’t be done. Hold on to that intuition: finite memory can’t count without bound. In Chapter 6 we’ll turn it into a proof, and in Chapter 7 we’ll give the machine more memory to fix it.

2.4 Running two machines at once

Suppose you want strings with an even number of b’s and ending in ab. You already have both machines. Just run them side by side, one finger on each: your state is now a pair (where machine 1 is, where machine 2 is). Accept when both accept. That’s the product construction:

Product construction

States \(Q_1\times Q_2\); start \((q_1,q_2)\); \(\delta((p,q),a)=(\delta_1(p,a),\delta_2(q,a))\). For and (∩): accept when both parts accept. For or (∪): accept when at least one does.

This little trick is the proof that regular languages are closed under union and intersection — an exam question we’ll answer properly in Chapter 5.

2.5 A machine that can guess: NFA

Designing “ends with ab” took some thinking about fall-back arrows. What if the machine could simply guess? “I’ll keep reading… and now I bet the final ab starts.” If the guess was right, it accepts:

digraph{rankdir=LR; node[shape=circle fontname="Helvetica"]; edge[fontname="Helvetica"]; s[shape=point]; p2[shape=doublecircle]; s->p0; p0->p0[label="a,b"]; p0->p1[label="a"]; p1->p2[label="b"];}

From \(p_0\) on a there are two arrows — a choice. From \(p_1\) on a there is no arrow — that guess just dies. This is a nondeterministic automaton. The rule: it accepts if at least one way of guessing reaches an accepting state. Picture it cloning itself at every choice; if any clone ends happy, the answer is yes.

Definition — NFA

Like a DFA, but \(\delta:Q\times(\Sigma\cup\{\lambda\})\to 2^Q\): each state and letter gives a set of possible next states (maybe empty), and \(\lambda\)-arrows can be taken without reading anything. \(w\) is accepted if some path spelling \(w\) ends in an accepting state.

2.6 Guessing is not magic: NFA → DFA

Here is a surprising and beautiful fact: guessing gives no extra power. Any NFA can be turned into a DFA that accepts the same strings. The trick: instead of guessing, keep track of every place the NFA could be right now. Your sticky note no longer says “\(p_0\)” — it says “\(\{p_0,p_1\}\)”. There are only finitely many such sets, so this is still a DFA.

Recipe: subset construction
  1. Start state = \(\{q_0\}\) plus everything reachable from it by \(\lambda\)-arrows (the λ-closure).
  2. For a set \(S\) and a letter: collect everywhere any state in \(S\) can go on that letter, then add the λ-closure.
  3. Repeat for every new set that appears. The empty set is a trap state.
  4. A set is accepting if it contains an accepting NFA state.

Let’s do it for the guessing machine above. Start at \(\{p_0\}\).

DFA stateon aon baccepting?
→ \(\{p_0\}\)\(\{p_0,p_1\}\)\(\{p_0\}\)
\(\{p_0,p_1\}\)\(\{p_0,p_1\}\)\(\{p_0,p_2\}\)
\(\{p_0,p_2\}\)\(\{p_0,p_1\}\)\(\{p_0\}\)yes (contains \(p_2\))

Read the first row slowly: from \(p_0\), an a could keep us in \(p_0\) or move us to \(p_1\) — so the new set is \(\{p_0,p_1\}\). Second row, on b: \(p_0\) stays at \(p_0\), \(p_1\) moves to \(p_2\) → \(\{p_0,p_2\}\).

Now look at what we got: three states, and if you rename \(\{p_0\}=q_0\), \(\{p_0,p_1\}=q_1\), \(\{p_0,p_2\}=q_2\), it is exactly the DFA we designed by hand in 2.2, fall-back arrows and all. The construction figured out the tricky arrows for us.

Notice the start state: not \(\{s\}\) but \(\{s,x,y\}\), because \(s\) can slide along λ-arrows to \(x\) and \(y\) for free. Forgetting that closure is the number-one mistake in this algorithm.

Where students lose points here
  • Forgetting the λ-closure (of the start state, and after every step).
  • Leaving out \(\emptyset\) — it’s a real state of the DFA, with arrows to itself.
  • Marking a set accepting only if it “is” final — the rule is: it contains a final state.
Your turn
  1. DFA for strings where every a is immediately followed by a b.
  2. DFA for strings of odd length.
  3. NFA for “second-to-last letter is a”, then convert it to a DFA.
Answers
  1. Remember: “all fine” (start, accepting), “owe a b” (just read a), and a trap. fine –a→ owe, fine –b→ fine, owe –b→ fine, owe –a→ trap.
  2. Two states that swap on every letter; the “odd” one accepts.
  3. \(p_0\) loops on a,b; \(p_0\) –a→ \(p_1\); \(p_1\) –a,b→ \(p_2\) (accepting). The DFA has four states \(\{p_0\},\{p_0,p_1\}, \{p_0,p_2\},\{p_0,p_1,p_2\}\) — they remember the last two letters — and the ones containing \(p_2\) accept.

Where we’re going next. Drawing machines is one way to describe a language. There’s a second way, which you’ve probably used in programming without knowing its theory: writing a pattern. That’s a regular expression — and it turns out to describe exactly the same languages.
