2. Finite automata: DFA and NFA BOTH

Intuition: a machine with a tiny, fixed memory

Imagine reading a string one letter at a time, left to right, never going back, and you are only allowed to remember one of a fixed, finite number of things — say, one of 3 sticky notes. At the end you must say “yes” or “no”. That is a finite automaton. Each state is one sticky note: “what do I need to remember about what I have read so far?”

A lexer (scanner) in an interpreter is exactly this kind of machine: it reads characters and decides where a number or identifier ends. That is why this chapter matters for the PL exam too.

2.1 DFA — deterministic finite automaton

Definition (Linz)

A DFA is a 5-tuple \(M = (Q, \Sigma, \delta, q_0, F)\) where

  • \(Q\) is a finite set of states,
  • \(\Sigma\) is the input alphabet,
  • \(\delta : Q\times\Sigma \to Q\) is the transition function — for every state and every symbol there is exactly one next state,
  • \(q_0 \in Q\) is the initial state,
  • \(F \subseteq Q\) is the set of final (accepting) states.

The extended function \(\delta^*(q, w)\) is the state you end in after reading all of \(w\) from \(q\). The language accepted is \(L(M) = \{w\in\Sigma^* \mid \delta^*(q_0, w)\in F\}\).

Deterministic means “no choices”: in each situation there is exactly one move. If some transitions are “missing” in a drawing, the convention is that they go to a trap state (a non-final state that loops to itself on everything) — you are dead and can never accept.

Example 1 — even number of b’s

What must I remember? Only whether I have seen an even or odd number of b’s so far. Two sticky notes: E (even) and O (odd). Reading an a changes nothing; reading a b flips.

Trace \(abba\): E →a E →b O →b E →a E. Ends in E (final) → accepted. Trace \(ab\): E → E → O → rejected. ✔

Example 2 — strings that end with ab

What must I remember? How much of the pattern “ab” I have just seen at the end:

  • \(q_0\): the string so far does not end with a or ab (“nothing useful”),
  • \(q_1\): it ends with a (half-way),
  • \(q_2\): it ends with ab (success — final).
digraph{rankdir=LR; node[shape=circle fontname="Helvetica"]; edge[fontname="Helvetica"]; s[shape=point]; q2[shape=doublecircle]; s->q0; q0->q0[label="b"]; q0->q1[label="a"]; q1->q1[label="a"]; q1->q2[label="b"]; q2->q1[label="a"]; q2->q0[label="b"];}

The tricky arrows are the “fall-back” ones. From \(q_2\) (ending with ab) reading a: the string now ends with a → \(q_1\), not \(q_0\)! From \(q_1\) reading a: still ends with a → stay.

Once you have seen aba you can never “un-see” it, so \(q_3\) loops on everything. From \(q_2\) (just read ab) a b gives abb, which ends with nothing useful → \(q_0\).

Recipe: designing a DFA
  1. Ask: what is the minimum I must remember about the prefix read so far to decide the answer later? (a remainder, the last few letters, a flag “already seen X”, a parity…)
  2. Make one state per possible “memory”. Mark as final those memories that mean “accept if the string ended now”.
  3. For every state and every letter, ask “what do I remember after this letter?” and draw the arrow. Count: states × letters arrows.
  4. Test on the empty string and 3–4 short strings.
Where the DFA points get lost
  • A missing transition in a DFA (unless you say “missing arrows go to a trap state”).
  • Forgetting to decide if the start state is final — it is exactly when \(\lambda\in L\).
  • The wrong fall-back in pattern-matching DFAs (Example 2 from \(q_2\) on a).

2.2 What a finite automaton cannot do

A DFA with \(k\) states can remember only \(k\) different things. So it cannot count without bound: \(\{a^nb^n\}\) would require remembering \(n\), which can be any number. That is the intuition behind the pumping lemma (Chapter 6): with more letters than states, some state must repeat (pigeonhole principle).

2.3 Running two DFAs at once: the product construction

Intuition

To check “even number of b’s and ends with ab”, run both machines side by side on the same input, with one finger on each. A state of the combined machine is a pair (state of \(M_1\), state of \(M_2\)).

Product construction

Given \(M_1 = (Q_1,\Sigma,\delta_1,q_1,F_1)\) and \(M_2 = (Q_2,\Sigma,\delta_2,q_2,F_2)\), build \(M = (Q_1\times Q_2, \Sigma, \delta, (q_1,q_2), F)\) with \[\delta((p,q),a) = (\delta_1(p,a),\ \delta_2(q,a)).\] For intersection take \(F = F_1\times F_2\) (both accept). For union take \(F = \{(p,q) \mid p\in F_1 \text{ or } q\in F_2\}\).

For our example the product has \(2\times 3 = 6\) states and the only final state is \((E, q_2)\). This construction is the proof that regular languages are closed under ∩ and ∪ (Chapter 5).

2.4 NFA — nondeterministic finite automaton

Intuition: a machine that can guess

An NFA may have several arrows for the same letter, none, or arrows labelled \(\lambda\) that it may take without reading anything. It accepts if at least one way of choosing leads to a final state. Think of it as a machine that clones itself at every choice; if any clone ends in a final state, the answer is yes.

Definition (Linz)

An NFA is \(M = (Q,\Sigma,\delta,q_0,F)\) like a DFA except \[\delta : Q \times (\Sigma\cup\{\lambda\}) \to 2^Q,\] i.e. each (state, symbol-or-λ) gives a set of possible next states (possibly empty). \(w\in L(M)\) iff some path labelled \(w\) goes from \(q_0\) to a state in \(F\).

NFAs are often much easier to design. “Ends with ab”: stay in \(p_0\) as long as you like, and guess when the final ab starts:

2.5 NFA → DFA: the subset construction

Theorem

For every NFA there is a DFA accepting the same language. So NFAs are not more powerful than DFAs — only more convenient. (The same question for Turing machines is FCS exam Q7, Chapter 12.)

Intuition

Instead of guessing, keep track of the set of all states the NFA could be in right now. There are only finitely many such sets (at most \(2^{|Q|}\)), so this is a DFA whose states are sets.

Recipe: subset construction
  1. λ-closure \(E(S)\): all states reachable from \(S\) using only λ-arrows (including \(S\) itself).
  2. Start state of the DFA: \(E(\{q_0\})\).
  3. For each DFA state \(S\) found so far and each letter \(a\): collect every state reachable from some \(q\in S\) by one \(a\)-arrow, then take the λ-closure. That set is the new DFA state.
  4. Repeat until no new sets appear. The empty set \(\emptyset\) is a trap state.
  5. A DFA state is final if it contains at least one NFA final state.
