18.1 Algebraic data types

Intuition

data defines a new type by listing its possible shapes. Each shape has a constructor (capitalised) that may carry values. You take values apart with pattern matching — exactly like lists (which are themselves just data List a = Nil | Cons a (List a)).



area (Circle 1)
area (Rect 3 4)
map area [Circle 1, Rect 2 5]



Maybe — “a value, or nothing”




safeHead ([] :: [Int])
safeHead [4,5]
safeDiv 10 0
lookupAge "bo" [("al", 30), ("bo", 25)]



18.2 Recursive data types and type constructors


The syllabus names “recursive data types” and “type constructors”. List and Tree below are
type constructors: they are not types by themselves but build a type from another (Tree Int,
Tree String).




lenL (Cons 'a' (Cons 'b' Nil))




fromList [5,3,8,1]
inorder (fromList [5,3,8,1,4])
member 4 (fromList [5,3,8,1,4])
size (fromList [5,3,8,1,4])
depth (fromList [5,3,8,1,4])


Recipe for trees = same as lists: one equation per constructor; recurse into sub-trees.



An expression tree and its evaluator (an interpreter in 6 lines)




eval (Add (Num 2) (Mul (Num 3) (Num 4)))



18.3 Type classes (ad hoc polymorphism)


A type class is a set of types that support certain operations — like a Java interface. Eq, Ord,
Show, Num are built in; deriving (Show, Eq) generates instances automatically.




describe True
describe (Rect 1 2)



18.4 An ADT in Haskell (information hiding via modules)




In a real module you export module Stack (Stack, empty, push, pop, top, isEmpty) where — the type
Stack without its constructor. Clients can’t see or build the list inside: that is information hiding.


top (push 3 (push 2 empty))
isEmpty empty



18.5 Laziness


Haskell evaluates an expression only when its value is needed (lazy / non-strict evaluation, call-by-need). So infinite
lists are fine as long as you use only a finite part (this is the lecture’s squares example).




take 5 squares
16 `elem` takeWhile (<= 16) squares
take 10 fibsLazy

Reading type errors

“Couldn’t match expected type [a] with actual type a” almost always means you wrote
xs ++ x (element where a list was needed) — use xs ++ [x] or x : xs. “Non-exhaustive
patterns” means you forgot a case (usually []).
