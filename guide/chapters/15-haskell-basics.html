15. Haskell basics: types, functions, lists PL

The mindset

In Java you write instructions: “set x to 0, loop, add…”. In Haskell you write definitions: “the sum of an empty list is 0; the sum of x:xs is x plus the sum of xs”. A function is like a maths function: same input ⇒ always the same output, and it changes nothing else (no side effects). There are no loops — recursion does that job. Nothing is ever modified — you build new values.

Function application binds tightest

f x + 1 means (f x) + 1. f x y is f applied to two arguments — no commas, no parentheses. To pass an expression, wrap it: double (3 + 4), not double 3 + 4.

15.2 Types

TypeValues
Int, Integerwhole numbers (fixed size / unlimited)

BoolTrue, False
Char'a' (single quotes)
String"abc" — it is just [Char]
[a]list: all elements the same type
(a, b)tuple: fixed size, types may differ
a -> bfunction from a to b

Lowercase type names like a are type variables: “any type”. length :: [a] -> Int works for lists of anything (parametric polymorphism). A constraint like Eq a => means “any type that supports ==”; Ord a supports <; Num a supports +; Show a can be printed.

:t 'a'
:t "hi"
:t (True, 'x')
:t length
:t (==)

Note: modern GHC shows length :: Foldable t => t a -> Int because it works on more containers than lists. For lists, read t a as [a]: length :: [a] -> Int. On the exam, the list version is what is expected. The same applies to sum, elem, foldr, foldl.

15.4 Lists: the one data structure you must master


How lists are built

A list is either empty [] or an element in front of a list: x : xs.
[1,2,3] is only shorthand for 1 : (2 : (3 : [])). That is why every list function has two cases:
[] and (x:xs).
