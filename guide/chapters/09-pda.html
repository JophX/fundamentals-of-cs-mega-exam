9. Giving the machine a stack: pushdown automata FCS

Grammars describe nested languages. What machine recognises them? Let’s go back to our door-keeper with sticky notes, who failed at \(a^nb^n\) because they couldn’t count. Give them one extra tool: a stack of plates. They can put a plate on top, take the top plate off, and look at the top plate — nothing else. No peeking lower down.

Now \(a^nb^n\) is easy: for every a, put a plate on the stack. For every b, take one off. If the stack is back to empty exactly when the string ends, the counts matched. And brackets? Put a plate on for “(”, take one off for “)”. A stack is exactly the memory that nesting needs: the last thing opened is the first thing closed.

Definition — NPDA (on your exam sheet)

\(M=(Q,\Sigma,\Gamma,\delta,q_0,z,F)\): states, input alphabet, stack alphabet \(\Gamma\) (the kinds of plates), transitions \(\delta\), start state, a bottom-of-stack symbol \(z\), accepting states.

A transition \((p,x)\in\delta(q,a,s)\) reads: “in state \(q\), reading \(a\) (or nothing, if \(a=\lambda\)), with \(s\) on top of the stack — go to \(p\) and replace \(s\) by the string \(x\)”. So \(x=\lambda\) pops, \(x=As\) pushes \(A\), and \(x=s\) leaves the stack alone.

9.1 The machine for \(a^nb^n\)

TransitionIn words
\(\delta(q_0,a,z)=\{(q_0,Az)\}\) and \(\delta(q_0,a,A)=\{(q_0,AA)\}\)for each a, push a plate \(A\)
\(\delta(q_0,b,A)=\{(q_1,\lambda)\}\), \(\delta(q_1,b,A)=\{(q_1,\lambda)\}\)for each b, pop a plate; after the first b we’re in \(q_1\), so no more a’s are allowed
\(\delta(q_0,\lambda,z)=\{(q_2,z)\}\), \(\delta(q_1,\lambda,z)=\{(q_2,z)\}\)back at the bottom: go to the accepting state \(q_2\)

Watch it run on \(aabb\). We write (state, what’s left to read, stack):

\((q_0,aabb,z)\vdash(q_0,abb,Az)\vdash(q_0,bb,AAz)\vdash(q_1,b,Az)\vdash(q_1,\lambda,z)\vdash(q_2,\lambda,z)\) ✔

Those snapshots are called instantaneous descriptions. The exam likes them because they show you understand how the machine moves.

9.2 Why the N matters here

For palindromes \(ww^R\), the idea is: push the first half, then pop and compare the second half. But when does the second half start? The machine can’t know — so it guesses, at every position, “maybe this is the middle”. One of those guesses is right.

With finite automata, guessing gave no extra power (Chapter 2). With stacks, it does: palindromes can be recognised by a guessing PDA but by no deterministic one. So:

regular \(\subset\) deterministic context-free (DPDA) \(\subset\) context-free (NPDA)

\(a^nb^n\) is in the middle class (a DPDA can do it — no guessing needed), \(ww^R\) is only in the outer one. Programming-language parsers use deterministic grammars, because a parser that must guess would be too slow.

9.3 Grammars and stack machines are the same power

Theorem

A language is generated by a context-free grammar if and only if it is accepted by an NPDA.

The direction grammar → machine is lovely and worth understanding: put \(S\) on the stack. If the top is a variable, replace it by the right side of one of its rules (guessing which). If the top is a letter, it must match the next input letter — pop it. If the stack empties exactly as the input ends, accept. The stack holds “what I still expect to see”, and the machine is simply acting out a leftmost derivation. That is precisely what a top-down parser does.

Where we’re going next. Grammars can be messy — λ-rules, rules that just rename, rules with long right sides. For a computer to parse efficiently, it helps to first rewrite the grammar into a tidy standard shape. That’s Chomsky normal form — and with it, a neat algorithm (CYK) that decides whether a string belongs to the language.
