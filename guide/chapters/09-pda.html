9. Pushdown automata FCS

Intuition: a finite automaton plus a stack

A DFA can’t count without bound. Give it a stack (a pile of plates: you can only add or remove on top) and it can: for \(a^nb^n\), push one plate per \(a\), pop one per \(b\), and accept if the pile is back to the bottom exactly when the input ends. PDAs recognise exactly the context-free languages — the stack is what a parser uses to match brackets.

Definition (exam appendix): NPDA

\(M=(Q,\Sigma,\Gamma,\delta,q_0,z,F)\): states, input alphabet, stack alphabet \(\Gamma\), transition function \(\delta: Q\times(\Sigma\cup\{\lambda\})\times\Gamma\to\) finite subsets of \(Q\times\Gamma^*\), start state, stack start symbol \(z\), final states.

\((p, x)\in\delta(q, a, s)\) means: in state \(q\), reading \(a\) (or nothing if \(a=\lambda\)), with \(s\) on top of the stack: go to \(p\) and replace \(s\) by the string \(x\) (leftmost symbol of \(x\) becomes the new top). So: pop = replace by λ; push \(A\) = replace \(s\) by \(As\); no change = replace \(s\) by \(s\).

Accepts \(w\) if some computation reads all of \(w\) and ends in a final state.

Example: \(\{a^nb^n\mid n\ge0\}\)

TransitionMeaning
\(\delta(q_0,a,z)=\{(q_0,Az)\}\), \(\delta(q_0,a,A)=\{(q_0,AA)\}\)push an \(A\) for each \(a\)
\(\delta(q_0,b,A)=\{(q_1,\lambda)\}\), \(\delta(q_1,b,A)=\{(q_1,\lambda)\}\)pop an \(A\) for each \(b\); once b’s start, no more a’s
\(\delta(q_0,\lambda,z)=\{(q_2,z)\}\), \(\delta(q_1,\lambda,z)=\{(q_2,z)\}\)stack back at bottom ⇒ go to final \(q_2\)

\(F=\{q_2\}\). Trace \(aabb\): \((q_0,aabb,z)\vdash(q_0,abb,Az)\vdash(q_0,bb,AAz)\vdash(q_1,b,Az)\vdash(q_1,\lambda,z)\vdash(q_2,\lambda,z)\) — accept. These triples (state, remaining input, stack) are instantaneous descriptions.

Example: even palindromes \(ww^R\) — uses nondeterminism

Push every letter; at some point guess “this is the middle” (a λ-move to a pop state); then pop and compare each letter with the top. A deterministic machine can’t know where the middle is — this language is CF but not deterministic CF.

9.1 CFG → PDA

Construction (the proof that every CFL has a PDA)

One working state. Push \(S\). Then repeat: if the top is a variable \(A\), replace it (λ-move) by the right side of some rule \(A\to x\) (guess which); if the top is a terminal, it must match the next input letter — pop it and read. Accept when input is used up and the stack is empty (at \(z\)). The PDA simulates a leftmost derivation.

9.2 Deterministic PDAs

  • DPDA: at most one possible move in every situation (and no choice between a λ-move and a reading move).
  • DCFL = languages of DPDAs. Regular ⊂ DCFL ⊂ CFL, both strict: \(a^nb^n\) is DCFL but not regular; \(ww^R\) is CFL but not DCFL.
  • DCFLs are closed under complement; CFLs are not. Programming-language parsers (LR) work with DCFL-style grammars because they must be fast (linear time).
  • Unlike finite automata, NPDAs are strictly more powerful than DPDAs.
