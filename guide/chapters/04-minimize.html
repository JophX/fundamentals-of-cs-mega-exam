4. Making machines small: minimization FCS

Two people design a DFA for the same job. One has 3 states, the other has 7. Are they really different machines? Often the 7-state one just has some states that are secretly the same — sticky notes with different names that mean the same thing. Minimization finds those and merges them.

When are two states “the same”?

When the future looks identical from both. If, from state \(p\) and from state \(q\), every possible rest-of-the-string leads to the same verdict (accept/reject), then it doesn’t matter which of them you’re in. They’re indistinguishable.

If there is some string that leads one to accept and the other to reject, that string distinguishes them — they must stay separate.

4.1 The marking algorithm

Rather than hunting for strings that are equal, we hunt for differences, starting from the obvious one and letting them spread:

Recipe
  1. Delete states you can’t reach from the start.
  2. Make a table with a cell for every pair of states.
  3. Round 0: mark every pair where one is accepting and the other isn’t. (The empty string already tells them apart.)
  4. Next rounds: for each unmarked pair \((p,q)\) and each letter: if the letter leads them to a pair that is already marked, mark \((p,q)\) too — that letter plus the old distinguishing string tells them apart.
  5. Stop when a round marks nothing new. Every unmarked pair can be merged.

Result: \(q_0\) and \(q_3\) are the same state. Merge them and you get exactly the 3-state machine from Chapter 2. Makes sense: both mean “nothing useful seen yet”.

Two facts worth knowing

The smallest DFA for a regular language is unique (apart from state names). So to check if two DFAs accept the same language, minimise both and compare — which means equivalence of regular languages is decidable.

Traps
