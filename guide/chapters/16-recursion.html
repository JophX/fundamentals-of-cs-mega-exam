16. Recursion and accumulators PL

No loops. So how do you do something for every element of a list? This chapter answers that, and it’s the most important chapter of Part III: once recursion “clicks”, every Haskell exam question becomes a variation on two patterns you’ll learn here.

How to think recursively (“trust the recursion”)

To write mySum (x:xs), pretend mySum xs already works. If mySum [2,3] is 5, then mySum [1,2,3] is 1 + 5. You only have to answer two questions: what’s the answer for the empty list, and how do I combine the first element with the answer for the rest.

Recipe (use it for every exam function)
  1. Write the type signature.
  2. Write the base case (f [] = …, or f 0 = …).
  3. Write the recursive case using f xs (smaller input).
  4. Trace it on a 2–3 element list by hand.

16.1 Pattern 1 — plain recursion



mySum [1,2,3,4]
myProduct [1,2,3,4]
myElem 3 [1,2,3]
myTake 2 "hello"
myDrop 2 "hello"
factorial 20


Trace mySum [1,2,3] = 1 + mySum [2,3] = 1 + (2 + mySum [3]) =
1 + (2 + (3 + mySum [])) = 1 + (2 + (3 + 0)) = 6. Notice the additions wait until the end — the
computer must remember them on the stack.

16.2 Pattern 2 — accumulators and tail recursion


Intuition

Carry the “answer so far” as an extra argument, like a loop variable. When the list is empty, the accumulator is the
answer. The recursive call is the last thing the function does — that is tail recursion: nothing waits on the stack,
so it runs like a loop in constant stack space.




template :: [Int] -> Int
template xs = go xs 0
  where
    go []     acc = acc
    go (y:ys) acc = go ys (acc + y)




myRev in O(n) — asked on both 2023 exams (10 p)




myRev "Hello"
myRev [1,2,3]


Trace: go [1,2,3] [] → go [2,3] [1] → go [3] [2,1] → go [] [3,2,1].
One : per element ⇒ O(n). The accumulator works like a stack of plates: the first element ends up at the bottom.


Not O(n)



++ copies its left list each time: \(1+2+\dots+n=O(n^2)\).
